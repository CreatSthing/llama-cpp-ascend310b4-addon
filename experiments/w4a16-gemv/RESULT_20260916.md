# Qwen2.5-1.5B W4A16 single-token GEMV probe

Target: Ascend 310B4, CANN 8.5.0, matrix shape `[1,1536] x [1536,8960]`.

## Result

| implementation | output tile | mean kernel time | verification |
|---|---:|---:|---|
| first manual W4A16 | 64 | 140.802 ms | exact |
| grouped W4A16 | 64 | 48.700 ms | cosine 0.99998218 |
| grouped W4A16 | 256 | 12.751 ms | cosine 0.99998218 |
| grouped W4A16 | 448 | 8.074 ms | cosine 0.99998218 |
| grouped FP16 baseline | 256 | 6.008 ms | exact |
| grouped FP16 baseline | 448 | 4.262 ms | exact |

The optimized W4A16 kernel is about 17.4x faster than the first correct
implementation, but remains about 1.89x slower than the matched FP16 vector
baseline. It should not be integrated into llama.cpp as a speed path yet.

## Applied official design ideas

- Split work by output columns across NPU cores.
- Copy contiguous blocks instead of individual values.
- Use queue-backed input/output movement and UB work buffers.
- Reuse one activation block across all output tiles owned by a core.
- Unpack a full quantization group with wide vector instructions.
- Accumulate integer weights first and apply the per-group scale once.

These follow the data-movement and tiling principles in the official CANN
FFN AntiQuant implementation. The official FFN INT4 AntiQuant kernel itself
is guarded for `__CCE_AICORE__ == 220`; its direct `AscendAntiQuant<int4b_t,
half>` primitive does not compile for the 310B4 m200 target.

## Failed parameter

Output tile 560 compiled but raised ACL error 507015 at runtime and produced
invalid output. Its packed half-row is not aligned for this copy/vector path.
Tile 448 is the fastest verified aligned configuration tested here.

## Next technical path

The remaining cost is INT4 unpack, cast to FP16, and vector arithmetic. The
official Incremental Flash Attention source demonstrates an INT4 x INT4 Cube
path plus multi-scale decomposition/reconstruction. A Qwen decode prototype
should test that hardware-native approach instead of further tuning the
FP16-vector fallback.
